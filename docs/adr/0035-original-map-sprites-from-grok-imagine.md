# ADR 0035: Original map sprites from Grok Imagine, used as ready-made sprites

- Status: Accepted
- Date: 2026-11-01
- Deciders: Owner (requested 2026-11-01 in Issue [#248](https://github.com/sekoya-solutions/sekoya-transit/issues/248))

## Context

[ADR 0032](0032-map-art-from-kenney-cc0-packs.md) draws every map object from Kenney CC0 packs, with 3D models baked to sprites by an editor tool. The owner now generates original, consistent isometric sprites with Grok Imagine (xAI) and wants them to replace the Kenney art object by object; more will follow. The first batch is the town and the forest industry chain (forest, sawmill, furniture factory). Each sprite already comes on the 320 x 400 px canvas of the 2x2 site sprites, with the block's ground diamond centered on the sprite's base, so no baking is needed. The earlier [Issue #16 ComfyUI pilot](../specs/art-pipeline.md) only validated feasibility; this decision is separate from it.

## Options considered

1. **Re-bake everything in the tool, feeding the new images in as sources.** Rejected: the tool renders 3D models, and an image copied through it gains nothing.
2. **Commit the new PNGs as they are and make the bake tool skip them (chosen).** The sprites use the same file names, import settings (128 pixels per unit, site pivot) and art set lookups as the baked ones, so no runtime code changes. The bake tool keeps producing the remaining Kenney art (iron mine, generic industry, stations, vehicles, road and rail atlas) and wires the original files into the art set.
3. **A separate folder and a second lookup in the art set.** Rejected as extra code for no gain: the lookup already falls back by industry id.

## Decision

- Original sprites are committed under `Assets/_Project/Art/Map/Baked/` with the names the art set expects (`building_house_0.png`, `building_industry_forest.png`, `building_industry_sawmill.png`, `building_industry_furniture_factory.png`). `MapArtBaker.OriginalSprite` marks them so the bake never overwrites them; the committed file is the only source.
- There is one town sprite (a cluster of five houses), so every town uses it; the four Kenney house sprites and the Kenney sources only they used (City Kit Suburban, `building-s`, `building-m`, the two conifers) are removed from the repository.
- Further replacements follow the same steps: commit the PNG under the existing name, mark the industry as `OriginalSprite`, and update the credits.
- Provenance: the images are generated by the owner with Grok Imagine and recorded in [CREDITS.md](../../CREDITS.md). They are the owner's own outputs under xAI's terms of service at the time of generation, not CC0, and the repository stays all rights reserved.

## Consequences

- Positive: the first game objects have a distinctive, original look; no runtime or save change; adding a sprite is a file drop plus one marker.
- Negative: the map mixes styles until all objects are replaced (soft 3D toy look next to Kenney's flatter renders); the originals cannot be regenerated by the bake, so the PNGs are the only source of truth; the legal status of AI-generated images is less settled than that of CC0 art.
- Follow-up: replace the remaining Kenney art as sprites arrive, then retire the Kenney packs, ADR 0032 and the bake tool pieces they no longer feed.
